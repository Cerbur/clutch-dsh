# Worktree 0.1.5 UI Polish Design

**Date:** 2026-08-25  
**Status:** Approved

## Goal

Improve the Worktree browser Consumer's Session context and Sidebar presentation
for the 0.1.5 release:

1. remove branch-context flicker when switching Sessions or while a conversation
   updates;
2. show the complete branch context in a hover card in both supported Session
   presentations;
3. align the Worktree Sidebar footer action with the native Sidebar typography
   and row geometry;
4. remove the redundant `WT` button from the collapsed Worktree surface rail.

The attached screenshots are visual references only. They do not add
implementation instructions beyond these four user requirements.

## Confirmed constraints

- DSH remains the source of truth for Workspace and Session identity, metadata,
  lists, and conversation content.
- The browser Consumer continues to use the existing `/api` Connection and
  shared Worktree Manager projection. No new transport, Host method, Provider
  field, or sidecar data is introduced.
- The existing generation and current-identity checks remain authoritative;
  stale asynchronous reads must never become visible.
- The current DSH rc.8 contract and native packages are not modified by this
  feature worktree.
- Changes to public UI behavior must be reflected in both `README.md` and
  `README.zh.md`; the package version remains the only version source.

## Design

### 1. Stable Session context projection

`worktree-context-store.ts` will retain the last complete Worktree view facts
per Workspace. A context refresh will distinguish the current identity from
ordinary DSH snapshot churn:

- updates that leave the current `sessionId` and `workspaceId` unchanged will
  not clear the visible context or start a redundant branch read;
- a Session change inside a Workspace will resolve immediately from the cached
  Workspace facts, then refresh those facts in the background;
- entering a Workspace without cached facts, an explicit Retry, or an identity
  change requiring new data may show the existing loading/no-context state;
- while a valid identity is being refreshed, its current resolved value remains
  visible until the replacement result is ready; a successful replacement is
  applied atomically;
- the current request generation and identity match guard still reject all
  superseded results.

This prevents conversation message snapshots from making a valid branch chip
disappear and reappear. It also avoids showing the previous Session's branch:
the new identity is resolved from its own cached facts, or the chip remains
absent when no safe facts exist.

The cache stores only browser-local, contract-shaped branch, Worktree, and
binding projections. It does not persist data, copy Session content, or expose
Provider/Git/Node objects.

### 2. Shared complete-value hover presentation

The existing Session-header context label and Hero context label will both use
the DSH primitive `HoverCard`:

- the chip keeps its current bounded width and ellipsis;
- the card opens with the native-compatible 500ms delay;
- card content contains the complete raw Workspace/branch context and can wrap
  long branch names;
- `title` and localized `aria-label` remain as browser and accessibility
  fallbacks;
- the Hero chip becomes hoverable without changing the native Hero controls or
  its placement calculation.

The hover card is presentation-only. It has no new state, RPC, mutation,
persisted value, or branch-name normalization.

### 3. Native-aligned Sidebar typography

`WorktreeModeAction` and its CSS will use the native Sidebar's inherited font
family and semantic tokens, with the same row-level font size, line height,
weight, icon sizing, gap, padding, and vertical alignment as the adjacent
native footer action. Active and accessible behavior remain unchanged. The
plugin will not import or replace the native Sidebar row component.

The implementation will prefer inherited native typography and existing DSH
tokens over screenshot-specific font declarations. The exact source-level
rules will be captured by Client regression assertions so future changes do
not reintroduce a visually independent footer row.

### 4. Collapsed surface behavior

The Worktree surface will keep its existing collapsed width and native footer
Worktree icon entry, but it will no longer render the surface-local `WT` rail
button. The redundant `railContent`/`railButton` presentation and related CSS
will be removed or made unreachable. Dialog portals and the expanded surface
remain unchanged.

## Error and lifecycle behavior

- First entry and explicit Retry preserve their existing loading/error
  surfaces.
- A background refresh error cannot replace a valid context with a false value;
  the existing request/error rules remain in force and no stale response can
  win.
- Context projection disposal still unsubscribes from DSH snapshots and
  clears browser-local state without touching DSH-owned data.
- Hover-card disposal follows React rendering; no global listener or custom
  overlay lifecycle is added.
- Collapsing the Sidebar does not change the active Worktree mode or the
  current Session context.

## Verification strategy

Focused tests will cover:

- no context reset or redundant read for same-identity conversation updates;
- immediate cached resolution when switching Sessions in one Workspace;
- stale response rejection after an identity change;
- complete-value hover cards in both Header and Hero components;
- wrapped long hover content and preserved accessibility fallbacks;
- native-aligned footer action typography and geometry;
- absence of the collapsed surface `WT` button while the native footer action
  remains available.

The feature worktree will run the focused Client tests first, then package
lint, typecheck, build, package tests, workspace checks, patch checks, and
`git diff --check`.
