# Source Optimization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce internal source-module size and duplication across the Worktree plugin while preserving every public export, Remote/Client contract, UI behavior, sidecar boundary, and failure-recovery rule.

**Architecture:** Apply conservative seam extraction. Keep existing public barrels and composition roots, move pure logic and cohesive React sections into internal modules, and make the old `worktree-view.ts` path a compatibility barrel. The refactor is validated by the current behavior suite plus focused tests for extracted pure functions.

**Tech Stack:** TypeScript, React/TSX, Node.js built-in test runner, pnpm, ESLint, Prettier.

## Global Constraints

- Preserve public exports from `src/index.ts`, `src/contract/index.ts`, `src/provider/index.ts`, `src/manage/index.ts`, and `src/client/index.ts`.
- Preserve Remote method names, JSON projections, Client Connection `/api` calls, and browser-only module boundaries.
- Preserve main, active Worktree, detached, repair, blank-session, ordering, refresh, retry, disposal, and failure-compensation behavior.
- Do not modify DSH source packages, DSH Project/Session facts, transcripts, prompts, or workspace business files.
- Do not add a second RPC or transport and do not import Node, Host, Manage, or Provider modules from `src/client/`.
- Remove code only after proving it is unused or behaviorally redundant; do not remove a public export solely because current tests do not import it.
- Update `package.json.version` from `0.1.3` to `0.1.4` in this release worktree and keep the existing build/prepare scripts unchanged.
