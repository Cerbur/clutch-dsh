# Workspace Branch Policy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the repository root define the release, feature-worktree, root-change, rebase, squash, and merge workflow, and make the plugin package documentation point to the bilingual README policy.

**Architecture:** Put workspace-wide workflow rules in the root `AGENTS.md`; keep package `AGENTS.md` focused on package boundaries and point its documentation rules to the root. This avoids introducing package-specific branch conventions.

**Tech Stack:** Markdown, Git documentation, Prettier, existing workspace validation scripts.

## Global Constraints

- Branch policy belongs in `/Users/yuancheng/Documents/Code/clutch-dsh/AGENTS.md`.
- A release branch starts from `main` and uses `release/<release-name>-<version>`.
- A package feature worktree uses `wt-<release-name>-<version>/<feature-name>`.
- A root/workspace update uses `base/feat-<feature-name>`.
- Each worktree is squashed to one scoped commit, rebased onto release before merge, and release is rebased onto main before packaging/publishing.
- The README policy applies to every runnable plugin under `packages/`.
- Do not change package behavior, package version, README bodies, or source files in this worktree.
