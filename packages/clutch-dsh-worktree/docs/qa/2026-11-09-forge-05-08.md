## Diagnosis and reproducible boundary

Direct native prompt admission held missing Worktrees for restoration, including
warm Sessions, cold replay, queue/steer, and a subscribed Forge panel. This was not
an adequate substitute for opening the actual composer.

Opening a live Session invokes `SessionSkillCatalog.list()` in
`packages/api/session-controller/src/skill-catalog.ts`. It calls
`workingDirectory.ensure(live, signal)`. The working-directory service commits the
project fallback before inserting its notification. Forge's inbox listener then
sees cwd outside the recorded checkout and does not hold for restoration.

Adding this one catalog read before prompt admission reproduced both failures:

- **05, managed:** cwd becomes the project root; plugin instruction selection
  attempts to resolve the missing bound checkout and throws
  `Workspace directory is unavailable inside the Worktree` (`UNKNOWN` in UI).
- **08, forgotten:** no active plugin binding blocks the turn; the model replies
  from the project root without an official recovery prompt. The active label disappears.

An official-only creation control used `forgePanel.requestWorktree`, then a real
model prompt to create the checkout. It never used Worktree creation or binding.
After retaining the checkout under a renamed sibling, the catalog read committed
`working-directory/change` and `agent/inbox/spliced`, changing cwd to the project:

`session-1deb3799-d6ab-4c8f-a39f-d93ddadfdd1f`

This confirms the 08 trigger is upstream rather than malformed plugin-created
records. The control still ran in the test profile with Worktree installed; it
isolates the native creation/catalog path, not a separate uninstall acceptance.
Earlier explicit restore API tests remain valid, but do not prove automatic UI recovery.

To reproduce upstream without modifying any Session records:

1. Create an official Worktree Session in a disposable repository and finish a turn.
2. While it remains live, rename its checkout to a retained sibling.
3. Open/reopen the Session so the composer fetches skills, then send a message.
4. Observe project cwd, missing active Worktree label and no restoration hold.

## Fix and regression

Only instruction selection changes. If native cwd already differs from the binding,
and historical path resolution returns a genuine `WorktreeProviderError` with code
`WORKTREE_NOT_FOUND`, no Worktree instructions apply. Other failures propagate.
The plugin never chooses a fallback directory or changes the binding.

Six focused tests cover root Workspaces, subdirectory Workspaces, historical
Git-root sidecar records, `EACCES`, Git failure and an unrelated error imitating
the unavailable-checkout code. The root and historical cases failed before the
fix with the exact reported error; all six pass afterward. Missing-path instruction
reads leave sidecar bytes and immutable Session cwd unchanged. Existing tests cover
normal instruction injection, moving outside the checkout and native recovery.
