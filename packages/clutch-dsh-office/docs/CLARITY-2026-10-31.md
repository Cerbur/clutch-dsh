## Findings and changes

The first performance pass capped rendering at one million pixels. On a large
window this rendered below CSS resolution and enlarged the result, visibly
blurring the kitchen. The final policy supports DPR 2 with an eight-million-pixel
budget, floored at CSS resolution (or native DPR when below 1). Extremely large
canvases can exceed that budget at the floor.

The trash can has **zero image textures**. Raising its texture limit cannot fix
the reported marks. Identical 5× close-ups with shadows on/off isolated the large
triangular bands to real-time shadow sampling. Texel-center correction alone did
not resolve the curved-surface artifacts. The final sampler:

- aligns receiver-plane depth correction with the nearest sampled texel center;
- never extrapolates comparison depth behind the receiver on curved triangles;
- uses -0.0004 static projection bias, retaining -0.00015 for character contacts.

This substantially reduces the trash-can side streaks while keeping floor
contacts and soft shadows. It is a conservative shadow approximation: thin
occluders at grazing angles can weaken. Original reconstructed lid/handle
irregularities and some magnified refrigerator shadow faceting remain; this is
not a geometry refinement or a claim of artifact-free arbitrary zoom.
No geometry, material, source delivery, atlas, or bake signature was changed.

The earlier approximately 30 FPS measurement used about one million pixels.
It does **not** describe this seven-million-pixel quality setting. Shared actor
resources, reduced texture uploads, lossless transport, cadence scheduling, and
idle/offscreen savings remain active. High-resolution animated rendering is
still GPU-bound; this change does not claim sustained 30 FPS on this device.

Windows-style source-build path selection was separately reproduced and fixed:
[Windows investigation](WINDOWS-ASSET-SELECTION-2026-10-31.md).
