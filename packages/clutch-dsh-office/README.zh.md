# clutch-dsh-office

[English](README.md) | 简体中文

胡闹厨房把 DeepSeek Harness 的活跃会话放进同一间 3D 厨房。活跃、待交互和未读完成会话
会成为鲸鱼娘，最多同时四位；场景下方只显示活跃、待交互和未读会话，空闲会话不展示。

## 安装

### 从 npm 安装

首个 npm 版本尚待发布，发布后使用：

```bash
dsh plugin --profile web add @cerbur/clutch-dsh-office
dsh web
```

### 从本地 checkout 安装

```bash
cd /absolute/path/to/clutch-dsh
pnpm install
pnpm --filter @cerbur/clutch-dsh-office build

cd /absolute/path/to/deepseek-harness
pnpm dsh plugin --profile web add /absolute/path/to/clutch-dsh/packages/clutch-dsh-office
pnpm dsh web
```

安装或更新素材后重启 DSH Web 或 Desktop，再刷新客户端。
插件仅使用 DSH 公开服务，无需修改 Harness 源码。

在 Windows 源码 checkout 中使用本机 Windows 路径；拉取更新后，先重新 build 再重启 DSH。
仅刷新页面不会重新构建素材。

## 使用

页头展示 **DSH Office**、从 `package.json` 读取的版本 Tag 和 **胡闹厨房**。场景不显示角色数量角标。

1. 在侧栏打开 **Office**，页面只有一间厨房和一份活跃会话列表。
2. 运行、待交互、未读完成会话各有一个角色资格；状态优先级为待交互、活跃、未读。
   原生运行中的子代理汇总到父会话，不另建角色。
3. 角色符合条件期间保留原位置槽位，先容纳四位，后来的等待空位；计数和列表始终包含超出部分。
4. 点击角色气泡或列表行打开对应原生会话。仅打开 Office 或本地预览不会确认未读，已读状态由 DSH 管理。
5. 双击版本 Tag 可进入一至四位角色的本地预览，再双击返回真实会话；单击不切换，模拟气泡和行不跳转。

本版共享会话看板取代此前的多工作区总览、单间导航和活动模拟按钮。
角色游走与会话状态独立，不把移动解释为实际工具执行、做饭、拿取或开冰箱。

## 要求与限制

- 需要 DSH Web Client，首版针对 `dsh-v0.2.1-rc.2` 验证，以及原生 Session、
  Workspace、UI Workspace 导航、layout、sidebar、renderer 与 locale 服务。
- 只展示 Host 列表中的非空白、未归档、非 subagent 会话，不包含仅 catalog 行。
  工作区关系不可用时标为 **未分组**。
- “最近”指当前原生列表中符合活跃条件的会话，不另查归档或历史。Office 不为投影保留会话、不读历史、
  不发起模型请求或写会话日志，也不持久化第二份未读状态。
- 离线或断连时撤下过期角色与列表，等待原生基线重连；没有时间戳时明确显示未知。
- 四角色场景使用 75% 显示比例和有限通道图，带停留、转身与相互避让；不是通用寻路或人群引擎。
- 减少动态效果时停止游走与眨眼；隐藏或离屏时暂停，离屏画布释放 GPU 资源并在进入视口时重建。
- 需要 WebGL 2，shader 或上下文错误显示明确的重新加载操作。
- 画布支持 DPR 2，采用八百万像素预算且不低于 CSS 分辨率（设备比例低于 1 时跟随设备）。
  超大窗口在 CSS 下限处可超过预算。高清动画需要更多 GPU 时间，30 FPS 是上限而非保证。
  文字标签保持原生 CSS 清晰度。
  固定厨房光照以完整分辨率缓存，角色、动态阴影与玻璃仍实时绘制。
  缓存额外使用 GPU 内存，离屏时释放；不支持 HDR 渲染目标的设备保留完整画质直接渲染。
  小道具使用 512px 纹理，大表面与角色最多 1024px。近距离放大时细节会减少，八次采样的软阴影边缘可能更粗。
  安装包中的厨房素材需要浏览器支持 WebP 图片解码。
- 保留已采用的 Blender 厨房和暖光，包括冰箱前独立蓝白条纹脚垫与鲸鱼地毯；不采用被否决的冰箱精修。
  源工程与原始导入保留，构建选择另行核验的中档派生模型，不同时加载全部精度。
  角色骨骼、形态键与动画保持；详见[素材交接](docs/BLENDER-ASSETS.md)。

- 展示时钟参考通知铃铛：初次采用原生更新时间，观察到运行变化后用观察时刻；未观察到完成切换时，完成时间以原生更新时间为基准，不冒充精确执行日志。缺失时间明确展示，不读取会话历史。
